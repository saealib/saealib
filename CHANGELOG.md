# Changelog

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/),
and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [Unreleased]

### Added

- **`ConfigurationCommittedEvent(version, changes)`** reports a published binding version to the callbacks. It fires once per publication, after the new version is live, and a commit point that leaves the configuration unchanged publishes nothing and fires nothing, so an ordinary run produces no event however many commit points it enters. `changes` holds one `ConfigurationChange(slot, previous, current, source)` per replaced binding slot, in `BINDING_SLOTS` order, where `source` is the origin the optimizer recorded for the component that now holds the slot (`"setter"`, `"direct assignment"`, or a preset source); a publication that replaced no slot, such as one that recompiled around a part changed in place, reports an empty tuple, and a rejected replacement fires no event. The event goes to the callback manager of the published version, so a handler registered on the manager a replacement installs receives it and the manager that replacement replaced does not; a handler that raises propagates to the caller but cannot veto the publication: the event is an observer notification sent after the publication completed, so the new binding version, the published snapshot, the bound slots, and the run state's binding version keep describing the new configuration. The event carries no parameter changes and adds no History channel ([#377](https://github.com/saealib/saealib/issues/377))
- **Re-inserted Pymoo and DEAP engines are rebuilt from a construction-time copy**: `PymooAlgorithm` and `DeapGenerateUpdateAlgorithm` copy their wrapped engine when constructed and record that `ask()` used it, so putting the same instance back into a run resets it to the construction-time configuration. A re-inserted Pymoo algorithm gets a fresh copy of the wrapped pymoo object with its initialization flag and infill population reset, and a re-inserted DEAP adapter gets a fresh copy of its strategy with its fitness class and last individuals reset; the copy is made again on every re-insertion and the construction-time copy is never consumed. A first-time instance is never rebuilt, so a setting changed after construction is honored until the instance is bound and used; a later re-insertion returns to the construction-time setting. If the construction-time copy was unavailable, the first insertion still runs and a re-insertion is rejected at the commit point with `pristine_copy_unavailable`. Re-inserted Pymoo and DEAP instances reproduce, generation by generation, a run that inserted a fresh instance with the same configuration, synchronously and (for Pymoo with `allow_partial_tell=True`) asynchronously; an optimizer holding them still pickles and resumes ([#374](https://github.com/saealib/saealib/issues/374))
- **A Pymoo algorithm's initial population size is checked at the commit point**: before publication, the size the wrapped algorithm will use after any rebuild (its `pop_size`, or a copied setup and first `ask` when it has none) is compared with the running population size, and a mismatch is rejected with `pymoo_pop_size_mismatch` while the version, slots, columns, and evaluation count stay unchanged. A first insertion is checked against the live instance so a setting changed after construction is honored, and a first run with a mismatched size stops at the entry commit point before `ask`. The adapter also checks its initial population size when it is used directly outside a run, and a wrapped algorithm whose size cannot be determined reports the `pymoo_pop_size_unverified` warning ([#374](https://github.com/saealib/saealib/issues/374))
- **Named state is invalidated at a replacement, entries repair their columns, and several replaced slots publish once**: a successful replacement clears each state key that the outgoing plan writes, the incoming plan reads, and the incoming plan does not write, comparing `(namespace, name, schema_version)`; the keys are computed from the compiled plans only when a plan is published, so an unchanged commit point does not pay for it. A plan whose components do not enumerate their reads and writes, and a state resumed from a checkpoint in a new process (where the flow that produced it is unknown), invalidate nothing and the first case reports a warning. The first commit point of `iterate()`, `run()`, `iterate_from()`, and `run_from()` adds the declared columns a resumed state lacks without publishing, raising an event, or changing a version, and an entry that changes nothing publishes nothing. Transitions of several slots replaced in one step run once each in binding-slot order and publish once ([#373](https://github.com/saealib/saealib/issues/373))
- **A replacement aligns the population, archive, and Pareto-archive columns by default**: after a component replacement is published, the default `AlignColumns` transition adds every column the incoming components declare and the collections lack, filled with the declared default, and drops a column that an outgoing component declared, no remaining component declares, and the initializer did not create. The `x` column is always kept and is never added to a collection that has none, a state without a record of the columns the initializer created is not changed by a drop (a warning reports it), and only the three state collections are aligned, never the offspring collections. A replacement carrying its own `transition=` uses that transition. Column changes are staged and applied after post-validation, so a rejected replacement leaves the collections unchanged; deletions happen only at a commit point after pending evaluations drain, while the first commit point of an entry adds missing columns only. A GA-to-PSO swap therefore completes with `velocity`, `pbest_x`, `pbest_f`, and `pbest_cv` set to their defaults, a second PSO after a GA starts from those defaults again, a Pymoo algorithm adds `pymoo_idx`, and a column a remaining comparator declares (for example `spea2_fitness`) stays ([#372](https://github.com/saealib/saealib/issues/372))
- **`Transition`, `Chain`, and `transition=` on component setters** run a change at a component replacement's commit point. `Optimizer.set_algorithm()`, `set_strategy()`, `set_surrogate_manager()`, `set_acquisition()`, `set_evaluation_planner()`, `set_feedback_builder()`, `set_evaluator()`, and `set_comparator()` accept `transition=`, and a `Transition` subclass implements `apply(tctx)` over a `TransitionContext` that exposes the run's state, problem, and random generator, the outgoing and incoming bindings, the replaced slots, the collections it may write, and staged column writes for `state.population`, `state.archive`, and `state.pareto_archive`; `Transition.from_function(fn)` wraps a function that declares no columns, and `chain(*parts)` / `Chain` apply several transitions in order. The commit point runs the transition after static validation and before publication, applies the staged column writes only after post-validation, and publishes the binding version, the plan, and the scheduler last, so a transition that raises, or a replacement whose required columns the staged writes do not produce, leaves the published configuration, the binding version, the collections, and the scheduler as they were and is rejected. A transition that declares `produced_columns()` is checked before it runs, a declared replacement completes (a GA to PSO swap is accepted when its transition adds `velocity`, `pbest_x`, `pbest_f`, and `pbest_cv`), a produced column with the wrong dtype or shape is rejected, and a transition that declares nothing reports a warning and is verified after it runs. `apply` is a generator: yielding a value raises `ConfigurationError` because evaluation requested by a transition is not available. The replacement record a setter keeps until the commit point is internal, is written to no checkpoint or pickle, and is dropped when its component is already published ([#364](https://github.com/saealib/saealib/issues/364))
- **A commit point can reject a component replacement with structured details**: `ReplacementRejectedError` (a `ConfigurationError`) reports the slots it put back in `changes` as `RejectedChange(slot, previous, candidate, source)` entries, the findings that caused the rejection in `diagnostics`, and the binding version of the configuration the optimizer kept in `version`. Two checks run before anything is published: a candidate algorithm or comparator must not require population columns that `state.population`, `state.archive`, or `state.pareto_archive` lack (`missing_population_column`, naming the missing columns and suggesting `Population.add_columns()` or a transition that produces them), and a candidate component in a run that writes npz checkpoints must not declare `state.checkpointable=False` (`state_not_checkpointable`, naming the component path). Replacing a GA with a PSO is therefore rejected at the commit point until a transition that adds `velocity`, `pbest_x`, `pbest_f`, and `pbest_cv` exists ([#361](https://github.com/saealib/saealib/issues/361))
- **`Population.add_columns()` and `Population.drop_columns()`** change the column schema of a population between generations. `add_columns(specs)` takes `PopulationAttribute` definitions, fills every row with each definition's default, and returns the names it created; a column that already exists with an equal definition is a no-op that leaves the structure and value versions unchanged, while a different definition raises `ValidationError`. `drop_columns(names)` removes columns and returns the names it removed; the design-variable, objective, constraint, constraint-value, candidate-identity, and objective-source columns stay, an archive also keeps its `key_attr` column and the observation columns of an `append` archive, and asking for any of them raises `ValidationError`; a column that a component in use requires is not checked, and dropping it makes the next `ask` or `tell` that reads it fail with a `KeyError`. Both operations bump the structure and value versions, invalidate cached values, and invalidate `Individual` views, like `append()` and `truncate()`; `Archive` and `ParetoArchive` inherit both. The initializer writes the columns it created without a component declaring them to the `runtime.base_columns` state key, which is exported with the other `runtime.*` keys and survives portable and pickle checkpoints; a checkpoint without the key loads with the record absent, which readers treat as unknown ([#355](https://github.com/saealib/saealib/issues/355))
- **`Result.best(criterion=None)` and `Result.front(criterion=None)`** select solutions with a `Comparator` as the criterion; omitting it uses the default criterion, which ranks feasible solutions first and then applies Pareto dominance. Feasibility comes from the per-constraint violations (`0` for an inequality, the constraint's `tolerance` for an equality). When no solution is feasible, the default criterion uses the first row with the minimum `cv` for a single-objective problem and the non-dominated rows among the minimum-`cv` rows for a multi-objective problem, while a supplied criterion ranks every row with the minimum `cv`. `result.x` and `result.f` are the default-criterion view, `best` returns one solution as `(x, f)`, and `front` returns the non-dominated set as `(x, f)` using the criterion's own sorter ([#343](https://github.com/saealib/saealib/issues/343))
- **`Problem(cv_aggregator=...)`** sets the aggregation that turns raw constraint values into `cv`, replacing `handler.compute_cv`; a plain callable `cv_aggregator(constraints, x, g)` works. The default aggregation is `sum_violation` (available from `saealib.problem`), the sum of the per-constraint violations, whose value is bit-identical to `StaticToleranceHandler`. The contract is `cv == 0` if and only if every violation is zero, plus monotonicity, and `cv` only orders infeasible solutions against each other ([#342](https://github.com/saealib/saealib/issues/342))
- **`Optimizer.set_comparator()`** sets the comparator that orders solutions during a run, and `OptimizationState.comparator` exposes it. Without an explicit comparator the default follows the number of objectives (`SingleObjectiveComparator` for one objective, `NSGA2Comparator` for several) and is recorded as a framework default, and an explicitly set comparator always takes precedence. The comparator is resolved before the default population size and before the initializer, because the NSGA-III default population and the initial ranking both depend on it; a comparator without a `direction` receives the problem's direction when it enters the slot, and `Optimizer.validate()` reports a comparator whose direction, per-objective weights, or reference points do not match the problem's objective count as `direction_length_mismatch`, `objective_count_mismatch`, and `reference_points_dimension_mismatch`. Islands resolve their own default comparator per `Optimizer`, while an explicitly shared instance stays shared. A comparator replaced during a run, through `set_comparator()` from a callback or between `iterate()` steps, is published at the next commit point: the run state, the handler-threshold copy, and the search use the replacement from the following generation, and the publication waits while asynchronous evaluations are pending ([#341](https://github.com/saealib/saealib/issues/341))
- **Flow step and named region iteration counters** are available on `OptimizationState`; `max_steps()` can stop after a chosen number of completed flows, and summary history records cumulative Repeat and Loop counts ([#332](https://github.com/saealib/saealib/issues/332))
- **Stage flow declarations** expose component connections and preserve named data transformations on compiler graph edges ([#319](https://github.com/saealib/saealib/issues/319))
- **History evaluation channel records `g` and `noise`**; checkpoints written without these columns load with them filled with NaN ([#303](https://github.com/saealib/saealib/issues/303))
- **`ComponentRef` and `TemplateStrategy`**: declared Stages reference components by `(slot, role)`, and each plan resolves its own copy of the declaration without modifying it ([#308](https://github.com/saealib/saealib/issues/308))
- **`objective_source` population column** records whether each row's objective values come from a true evaluation (`0`), a surrogate prediction (`1`), or an imputed fallback (`2`); `255` marks an unknown source. Populations and archives built by the library initializers always carry it, and `PSO` and `PymooAlgorithm` keep it when they rebuild the population ([#311](https://github.com/saealib/saealib/issues/311))
- **`Stage.execution_boundary`**: `"transaction"` (default) runs a Stage on its declared reads, `"state"` gives the Stage and its callbacks the whole run state; any other value raises `ValidationError` when the plan is prepared ([#309](https://github.com/saealib/saealib/issues/309))

### Deprecated

- **`Problem(comparator=...)` and `Problem(eps_obj=...)`** emit a `DeprecationWarning`; configure the comparator, including its objective tolerance, with `Optimizer.set_comparator()` instead. Values passed to `Problem` keep working and are treated as explicit optimizer settings: a comparator passed to `Problem` is adopted as the optimizer's explicit comparator, and `eps_obj` seeds the default comparator's tolerance. A `Problem` keeps exposing the default comparator derived from its objective count, and a state created or loaded without an optimizer uses it; resume with `run_from()` or `iterate_from()` to keep the optimizer's comparator ([#341](https://github.com/saealib/saealib/issues/341))
- **`Problem(eps_cv=...)`** emits a `DeprecationWarning`. Its value is a search-time relaxation: it seeds the default handler's `feasibility_threshold`, which the runtime copies onto the comparator's `eps_cv` every generation, and it widens what the search ranks as feasible without changing reported feasibility. Without it the relaxation is `0.0`, and the comparator, archive, and `DecompositionComparator` share that `0.0` default: built-in comparators default `eps_cv` to `0.0` instead of `1e-6`, matching `ParetoArchive`, `DecompositionComparator`, `Problem`, and `StaticToleranceHandler`. A comparator whose `eps_cv` exceeds zero keeps `cv <= eps_cv` for ordering; the reported feasibility of `Result`, the history, training sets, and the archive comes from the constraint definitions ([#342](https://github.com/saealib/saealib/issues/342))
- **Direct `execute_strategy_step()` calls with asynchronous evaluation** emit a `DeprecationWarning`; use `Optimizer.iterate()` or `Optimizer.run()` ([#329](https://github.com/saealib/saealib/issues/329))
- **`Population.dense_view`, `Archive.dense_view`, and `ParetoArchive.dense_view`** emit a `DeprecationWarning`; use `dense_numeric_view` ([#329](https://github.com/saealib/saealib/issues/329))
- **Overriding `build_graph(provider)` in a custom `OptimizationStrategy`** emits a `DeprecationWarning` once per strategy class; write the strategy as a `TemplateStrategy` with a declared `Pipeline` instead. A plain subclass of a built-in strategy does not warn, and a strategy that lowers its own graph keeps using its hand-declared `requires_surrogate` attribute ([#340](https://github.com/saealib/saealib/issues/340))

### Removed

- **Unused execution protocol aliases, a private defaults forwarding method, and compiler rule re-exports outside `__all__`** were removed; use the canonical execution protocols, `Optimizer.resolve_defaults()`, or the implementation modules ([#329](https://github.com/saealib/saealib/issues/329))

### Changed

- **A part replaced inside a published component is applied at the next commit point**: a component declares its parts in `contract()`, so writing `ga.crossover` or a Pymoo algorithm's `allow_partial_tell` between generations is observed at the next commit point and treated as a replacement — the run drains, validates, and publishes one new binding version with the new executable plan, and the checks added for replacements apply, so a part that declares `state.checkpointable=False` stops a run that writes npz checkpoints with the `state_not_checkpointable` diagnostic. Writing a parameter value that no contract declares, such as `ga.crossover.prob`, `pso.w`, a surrogate's `alpha`, or `comparator.eps_cv`, changes neither the version nor the plan, and a rejected in-place change is not put back, because the change belongs to the component rather than to the slot the rejection restores. Reading the contracts costs about a millisecond per commit point for a GA configuration and about half of that for a PSO one, measured against a cheap objective; next to an expensive evaluation that is negligible ([#363](https://github.com/saealib/saealib/issues/363))
- **A rejected replacement puts the published configuration back**: the slots, the preset, the feature-encoder selection, and `_configuration_version` return to the values of the last published binding version, while `_last_published_bindings`, the state's binding version, evaluations, the archive, and History stay as they were. A rejection is raised as `ReplacementRejectedError` when it comes from the configuration gate or a commit-point check, and keeps the original type and message (for example `StalePlanError`) when preparation failed for a structural reason. `Optimizer.iterate_from()` after a rejection therefore starts from the published components and publishes nothing for the rejected change, and the optimizer only announces the checkpoint format for the `checkpoint_*` arguments of `run()`, `iterate()`, `run_from()`, and `iterate_from()` ([#361](https://github.com/saealib/saealib/issues/361))
- **Multi-objective results are recomputed from the main archive**. `Result.x`/`Result.f`, `minimize()`/`maximize()`, the experiment summary, and the result plots use the default criterion instead of returning the search-side Pareto archive, so a multi-objective result is the non-dominated set of truly evaluated main-archive rows and can differ from `pareto_archive`, for example in a run that uses ε relaxation. Single-objective `x`/`f` keep their values, `x` stays `None` for a non-numeric search space, and an empty archive still raises a `ValidationError` ([#343](https://github.com/saealib/saealib/issues/343))
- **Feasibility is decided by the constraint definitions**. A solution is feasible when every per-constraint violation after its own tolerance is zero (`g(x) <= threshold` for an inequality, `|h(x)| <= tolerance` for an equality), independent of how violations are aggregated into `cv` and of any ε relaxation used during search. `Result`, the history's `best_f` and `feasible_ratio`, the `FeasibilityClassificationSet` training set, and `ParetoArchive` all use that decision; the algorithm factory and the initializer bind the problem's constraints to the Pareto archive after it is created, so an archive class keeps its constructor, and the archive re-derives feasibility from its `g` column instead of following the handler threshold, and falls back to `cv <= eps_cv` only when the constraints or the column are unavailable. A Pareto archive restored from a portable checkpoint or a pickle rebuilds its stored rows under the bound constraints, so rows the constraints reject, or that the feasibility-first rule dominates, are dropped while the remaining rows keep their ids and values. A multi-objective Pareto front recorded during an ε-constrained run therefore keeps the strictly feasible non-dominated solutions when any exist and the minimum-cv front otherwise, and `feasible_ratio` reports the strictly feasible fraction while `min_cv` remains the exploration diagnostic ([#342](https://github.com/saealib/saealib/issues/342))
- **Constraint tolerances default to research convention**: `EqualityConstraint.tolerance` and `PymooProblem.eq_tolerance` default to `1e-4` (CEC 2006 and pymoo) instead of `1e-6`, and inequality thresholds stay `0.0`. Equality-constrained problems therefore shift their `cv` by up to `1e-4` per equality constraint and can report different feasible sets and Pareto fronts. The comparator `eps_cv` default changes from `1e-6` to `0.0`, which can change which row is ranked first when a row carries a positive violation up to `1e-6`: such a row counts as infeasible. `eps_obj` is unchanged ([#342](https://github.com/saealib/saealib/issues/342))
- **The comparator is read through `state.comparator` during a run**; `problem.comparator` is read by the compatibility path that adopts a comparator passed to `Problem`, and by a standalone compilation without an optimizer, where `ComparisonService` resolves from the problem's comparator. The initializer, constraint-handler threshold copies, training sets, selections, PSO, callbacks, the feedback fallback, the compiler's `ComparisonService` binding, and the direction diagnostics all use the comparator resolved for the optimizer, so the epsilon threshold a handler writes each generation reaches the object the search orders solutions with without changing the comparator binding or re-preparing the plan. Portable checkpoints do not store the comparator, and the checkpoint schema version does not change; pickle checkpoints keep the Optimizer object together with its comparator. The constraint and objective tolerances are excluded from the plan signature because a run rewrites them ([#341](https://github.com/saealib/saealib/issues/341))
- **Strategy surrogate requirements are derived from the declared flow**. `requires_surrogate` is a plain attribute holding the declared value, and the configuration diagnostics derive the effective requirement for a `TemplateStrategy` that keeps the standard lowering: it is `True` when any Stage, also inside nested Repeat, Loop, or Branch regions, refers to the surrogate manager slot through a `ComponentRef` or holds a surrogate manager directly, and that value decides the `missing_surrogate_manager` and `missing_acquisition` errors. The attribute is the declared value and not the effective requirement: a `TemplateStrategy` that declares nothing, including `GenerationBasedStrategy`, has `None`, `DirectStrategy` and `SteadyStateStrategy` have `False`, and `IndividualBasedStrategy` and `PreSelectionStrategy` have `True`; a class attribute, an attribute inherited from a mixin, an instance assignment, and a value restored from a pickle or a spec all count as the declaration, and `GenerationBasedStrategy` has `None` whether or not its flow has surrogate-only generations. Code that reads `strategy.requires_surrogate` as a boolean therefore does not see the effective requirement; check a configuration with `Optimizer.validate()` or `Optimizer.contract_diagnostics()` and its `missing_surrogate_manager` finding instead. `GenerationBasedStrategy(0)` requires neither a surrogate manager nor an acquisition, while `GenerationBasedStrategy(gen_ctrl)` with surrogate-only generations requires both. A declaration that contradicts the derived requirement is reported as a `contradicting_surrogate_requirement` WARNING diagnostic, and a strategy with a custom `build_graph` uses its declared attribute; restoring a spec that recorded `requires_surrogate=false` for a template whose flow uses a surrogate reports that WARNING and the run continues with the flow-derived requirement. The built-in constructor shorthand bundles default policy components: `IndividualBasedStrategy(evaluation_ratio)` and `PreSelectionStrategy(n_candidates, n_select)` produce the same plan and results as the declaration combined with explicitly set default policy components, an explicitly set component wins over the shorthand's default, and an in-place change of a shorthand parameter takes effect at the next commit point without affecting an explicitly set component ([#340](https://github.com/saealib/saealib/issues/340))
- **Algorithm metadata and built-in declarations are streamlined**. `Algorithm` provides `get_required_attrs() -> []`, `population_class -> Population`, and `archive_class -> Archive` defaults, so a minimal algorithm implements only `ask()`/`tell()` and runs with the standard `Population`/`Archive` and schema; metadata overrides that only restated the defaults (`GA`, `GenomeGA`, and the standard collection overrides of `PSO`, `PymooAlgorithm`, and `DeapGenerateUpdateAlgorithm`) are gone, and the algorithm slot stays duck-typed with no ask/tell or `Algorithm`-inheritance check. Runtime-observed declaration repairs declare the evaluation planner's candidate/request ID allocator reads and writes, `ComparatorWorstFallback`'s main-population read and its held `inner` builder part, and the comparator-using training sets' `ComparisonService` requirement (`TopKBipartitionSet`, `LevelBasedSet`, `PairwiseComparisonSet`, `ReferencePointComparisonSet`); `GA` now declares its integer/categorical variation children in parts. Contract checking reports a non-blocking `undeclared_part` WARNING naming the parent and attribute when a component attribute holds a child component that is not declared in `parts`; declared children, plain data attributes, and registered parts produce no warning, `part_contract_mismatch` stays an ERROR, and `Optimizer.validate()` still returns ERROR findings only ([#337](https://github.com/saealib/saealib/issues/337))
- **Context-dependent hooks take a trailing, keyword-only, required `ctx`** annotated `OptimizationState | None`: `ParentSelection.select(population, n_pair, n_parents, rng, *, ctx)`, `SurvivorSelection.select(pool, n_survivors, *, ctx)`, `EvaluationPlanner.plan(candidates, acquisition, *, ctx)`, `FeedbackBuilder.build(candidates, prediction, evaluation, evaluated_indices, *, ctx)`, `TrainingSet.build(archive, population, candidate_x=None, *, ctx)`, `AcquisitionFunction.prepare(archive, *, ctx)` and `.evaluate(candidates_x, prediction, archive, *, prepared=_UNSET, ctx)`, and `SurrogateManager.fit(archive, *, ctx)` and `.predict(candidates_x, archive, *, refit=True, ctx)`. Calls that pass `ctx` positionally or omit it raise `TypeError`; pass it by keyword, and custom overrides declare `ctx` the same way. Standalone calls outside a run pass `ctx=None` explicitly. Selection needs comparison and randomness, so every concrete built-in selection (`TournamentSelection`, `SequentialSelection`, `LinearRankSelection`, `TruncationSelection`) raises `ValidationError` for `ctx=None`, and other families keep their existing required-context rejections. Selection's public signature now names `OptimizationState | None` instead of the private `_SelectionContext` protocol, which is no longer public or referenced. `Surrogate.fit`/`predict`, crossover/mutation bodies, `Comparator`, `Decomposition`, and `Variable` remain context-free, and the meaning of the `rng`, `prepared`, `refit`, and `candidate_x` arguments is unchanged ([#336](https://github.com/saealib/saealib/issues/336))
- **`FeatureEncoder` defaults** are selected during execution preparation when the prepared strategy consumes the encoder. `VectorSpace` uses identity encoding and reports INFO with its source and reason; `PermutationSpace` and `SequenceSpace` retain their built-in encodings and report a non-blocking WARNING recommending explicit selection because encoding affects surrogate learning. Explicit encoders supplied through `SearchSpace.services` take priority, and `minimize()`, `maximize()`, and existing examples continue to run without encoder arguments. Direct `encode_features()` calls use the same supported defaults and emit a Python `UserWarning` when no encoder is registered. Standalone `ArchiveObjectiveSet` builds against a context without a prepared encoder follow the same defaults and warning, while a prepared or explicitly registered encoder keeps priority without the default warning ([#334](https://github.com/saealib/saealib/issues/334))
- **Component defaults** are selected from ordered configuration sources during execution preparation, and compiler diagnostics report the selected source and reason; comparators expose facts used by composition rules, including `aligns_population_to_reference_points` for comparators whose default population size follows their reference points. The strength-ranked default-hint mechanism (`DefaultResolver`, `DefaultHintProvider`, `DefaultContext`, `BuiltinDefaultProvider`, and component `default_hints()`) was removed, and custom `default_hints()` implementations are no longer consulted; set components through setters or direct assignment, user or bundled presets, strategy defaults, or Stage-local components, and set sizes through `pop_size`/`max_fe`, an explicit initializer, or termination. An acquisition paired with a surrogate manager follows the manager that is actually selected, and an explicitly supplied acquisition keeps priority ([#255](https://github.com/saealib/saealib/issues/255))
- **Optimizer configuration checks** use structured diagnostics from the prepared component bindings for missing components, planner and feedback requirements, surrogate and acquisition needs, objective directions, and evaluator lifecycle consistency. Compiler flow diagnostics report ERROR for unregistered transforms, provable transform-chain contradictions, and known transform outputs incompatible with their destinations even when the source kind is unknown. `Optimizer.validate()` resolves defaults non-destructively, so an optimizer with unset components returns no validation errors, and it remains a `list[str]` of ERROR findings whose messages carry diagnostic codes; WARNING reports requirements that cannot be verified, and INFO and WARNING remain available through diagnostic access without blocking execution ([#333](https://github.com/saealib/saealib/issues/333))
- **Execution plans** share preparation logic: adapters, services, and component bindings are resolved against the problem used by the runtime, and runtime capabilities are read from its provider across startup, resume, replacement, recompilation, and direct strategy steps; direct steps reject verification ERROR diagnostics ([#317](https://github.com/saealib/saealib/issues/317))
- **Stage flow verification graphs** use occurrence-qualified call IDs such
  as `ask__proposer`; repeated region names receive occurrence suffixes. They
  include verification call and external state nodes in `build_component_graph`
  and preserve declared transforms and schema bindings. Unused operators are
  no longer represented as nodes, automatic `dense_numeric_view` adapters are
  no longer inserted, and schema variables keep their declared names. State
  edges connect each reader to the active producer across branch and loop
  joins. Transform declarations control schema binding carry-through, so
  `encode_features` does not preserve `representation`. The sequential runtime
  executes framework components with roles and skips nodes used only for graph
  verification.
  Stages with unknown flow report one `cannot_verify_stage_flow` warning;
  custom strategies should call `decompose_structured_graph` after lowering to
  include flow edges ([#319](https://github.com/saealib/saealib/issues/319))
- **Planned evaluation flow** now verifies evaluator observations through
  `EVALUATION_UPDATES` and `EVALUATED_OFFSPRING` using the declared transforms
  ([#319](https://github.com/saealib/saealib/issues/319))
- **Stage state writes** replace inferred producers with state sources, while
  unknown Stage flow clears producers that can no longer be verified
  ([#319](https://github.com/saealib/saealib/issues/319))

### Fixed

- **Asynchronous evaluation works with genome-keyed problems.** `AsyncEvaluationScheduler` records the genome of each evaluated candidate in the archive and the Pareto archive, so a genome-keyed search space completes its run instead of stopping with `Archive.add() requires a genome for duplicate detection`; duplicates stay subject to the archive's duplicate policy, and every evaluation still counts in `fe` ([#367](https://github.com/saealib/saealib/issues/367))
- **`PostSurrogateFitEvent` handlers in a `GenerationBasedStrategy` run receive the run state as `event.ctx`**, so `gen`, `fe`, `population`, and `archive` can be read from it like from the other generation-based events ([#368](https://github.com/saealib/saealib/issues/368))
- **The History summary's `feasible_ratio` and `min_cv` describe the truly evaluated rows of the population**, so a predicted row's placeholder constraint value does not count as a feasible solution; both values are NaN when no population row is truly evaluated, and a population without an `objective_source` column counts every row ([#369](https://github.com/saealib/saealib/issues/369))
- **`run()` returns the state the run ended with**, including for asynchronous flows with region nodes such as `GenerationBasedStrategy` with `AsyncEvaluationScheduler`: `run()` and `run_from()` return the state the runtime finished with, so its `fe`, `gen`, `pending_evaluations`, `evaluation_plan_state`, population, and archive describe the end of the run and `fe` matches the recorded evaluation history. `iterate()` and `iterate_from()` keep yielding one state per generation boundary ([#365](https://github.com/saealib/saealib/issues/365))
- **A `Pipeline` that evaluates with `TrueEvaluationStage` records those evaluations in the History**, one row per evaluated batch with the evaluated candidate IDs, the true objective values, and the `fe_before` / `fe_after` of the evaluation channel, so the channel's rows, `state.fe`, and the last `fe_after` agree as they do for the plan-based flows. The batch's request ID comes from the run's request allocator, and `PostEvaluationEvent` keeps observing the state before the batch is counted with its `request_id`, `status`, and `candidate_ids` unset. A candidate ID that a multi-request plan reports in more than one update of the same request is counted once, so a state evaluation count can no longer exceed the recorded evaluations ([#366](https://github.com/saealib/saealib/issues/366))
- **Resuming with a component already in its slot aligns the resumed state before the first `ask`**: the first commit point adds the population, archive, and Pareto-archive columns the bound component declares, so a GA state resumed with a PSO in the algorithm slot continues, and a rejected component left in a slot raises a `ConfigurationError` at that commit point, including a state loaded from a portable checkpoint by another process ([#373](https://github.com/saealib/saealib/issues/373))
- **The deprecation warning for overriding `build_graph(provider)` is attributed to the code that runs the optimizer**, so a script that runs the optimizer sees it under the default warning filters, which show deprecation warnings attributed to `__main__` ([#354](https://github.com/saealib/saealib/issues/354))
- **Setting the same component again leaves the published plan in place.** Re-inserting a component instance through a setter or by attribute assignment keeps the binding version when the configuration is unchanged, and replacing A by B and back to A between two commit points publishes nothing; a different instance in a binding slot, an in-place strategy attribute change, a pipeline edit, and a `set_preset()` call each publish one new version at the next commit point, while replacing the initializer or the termination does not publish because the plan does not contain them ([#356](https://github.com/saealib/saealib/issues/356))
- **A component replacement rejected at a commit point does not stay in the Optimizer's resolved configuration.** The Optimizer keeps the configuration it last published, and a run resumed with `iterate_from()` starts from it: if the rejected slot is still set, validation at the commit point raises `ConfigurationError`, and the run resumes once the slot is fixed. This also holds after a pickle checkpoint of the Optimizer ([#346](https://github.com/saealib/saealib/issues/346))
- **Built-in strategy pipeline replacements** affect prepared runs at the next safe commit point, including changes made in nested flows; asynchronous runs wait for outstanding requests to finish, and replaced ask stages keep their own count ([#328](https://github.com/saealib/saealib/issues/328))
- **Checkpoint save points**: the initial `iterate()` state and resumable boundaries can be saved, asynchronous wait points are accepted only when resume can reconstruct them, pending requests are checked for reattachment and feedback consistency, a `GenerationBasedStrategy` run-end callback with an open region is accepted when its evaluation plan has no deferred requests and rejected otherwise, schema-1 acquisition results restored from pickle can be saved in portable format, and portable checkpoints do not require a serializable evaluator; asynchronous `GenerationBasedStrategy` runs that terminate inside a generation while true evaluations remain in flight may not resume to the same result from the state returned by `run()`, so save at `GenerationEndEvent` or from a `RunEndEvent` callback ([#325](https://github.com/saealib/saealib/issues/325))
- **Compiler diagnostics** report acquisition channels whose surrogate output lacks required uncertainty, is unavailable, or cannot be verified; `Optimizer.validate()` uses the same check before compilation ([#320](https://github.com/saealib/saealib/issues/320))
- **Direct asynchronous strategy steps** block until in-flight requests finish and return without running the step; the next call uses the current components. An explicit recompile requested while requests are in flight is retained until they finish ([#317](https://github.com/saealib/saealib/issues/317))
- **Strategy and Pipeline specs** preserve nested declarations, controls, component references, and explicit stage components; nested values build recursively, and unsupported values report their location. `to_spec` rejects non-importable local classes and shared instances with a location; `Optimizer.save_preset` uses the same validation ([#318](https://github.com/saealib/saealib/issues/318)).
